# Sources

These sources support the skill's distinction between AI-pattern convergence,
usable design, accessibility, responsive behavior, and implementation quality.
They are references for agent reasoning, not a claim that any source provides a
universal AI-authorship detector.

## AI-pattern and design-quality references

1. [Impeccable: Slop](https://impeccable.style/slop) — catalog of recurring
   AI-generated UI patterns, including purple gradients, repeated cards, generic
   copy, motion, typography, contrast, and layout problems.
2. [A List Apart: “Successful” or “Unsuccessful”: the Post-“Good Design” Vocabulary](https://alistapart.com/blog/post/successful-or-unsuccessful-the-post-good-design-vocabulary/) —
   argues that surface polish and fidelity are not design quality; evaluate
   goals, constraints, context, research, and outcomes.
3. [Figma: What is Good Design in the Age of AI?](https://www.figma.com/blog/what-is-good-design-in-the-age-of-ai/) —
   discusses familiar layout patterns, homogeneity, pragmatism, and grounding
   generated output in real team styles and methods.
4. [Nielsen Norman Group: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) —
   explains why interfaces should not contain information that is irrelevant or
   rarely needed.
5. [Nielsen Norman Group: Aesthetic-Usability Effect](https://www.nngroup.com/articles/aesthetic-usability-effect/) —
   documents that attractive interfaces can be perceived as easier to use, which
   is why visual polish must not be mistaken for functional quality.
6. [Nielsen Norman Group: 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) —
   provides checks for system status, real-world language, user control,
   consistency, error prevention, recognition, and helpful recovery.

## Accessibility and responsive references

7. [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) — normative accessibility
   requirements and success criteria.
8. [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow) — content
   should reflow without loss of information or ordinary two-dimensional reading
   scroll at narrow widths and enlarged text.
9. [W3C: Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible) —
   keyboard-operable interfaces need a visible focus indicator.
10. [W3C: Error Identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification) —
    detected input errors must identify the affected item and describe the error
    in text.
11. [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) —
    pointer targets need sufficient size or spacing, with documented exceptions.
12. [W3C: Consistent Navigation](https://www.w3.org/WAI/WCAG22/Understanding/consistent-navigation) —
    repeated navigation mechanisms should remain consistent.
13. [MDN: HTML accessibility](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/HTML) —
    semantic HTML, labels, headings, and native controls improve accessibility.
14. [MDN: Mobile accessibility](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/Mobile) —
    mobile interaction, touch, viewport, and responsive accessibility concerns.
15. [MDN: Responsive design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design) —
    responsive layouts must adapt to different screen sizes and input contexts.
16. [web.dev: Learn Responsive Design](https://web.dev/learn/design/welcome) —
    covers media queries, macro/micro layouts, typography, responsive images,
    theming, accessibility, and interaction.
17. [Apple Human Interface Guidelines: Layout](https://developer.apple.com/design/human-interface-guidelines/layout) —
    layout, hierarchy, adaptation, and content-focused composition.
18. [Apple Human Interface Guidelines: Typography](https://developer.apple.com/design/human-interface-guidelines/typography) —
    typography as hierarchy, legibility, and communication.
19. [Apple Human Interface Guidelines: Motion](https://developer.apple.com/design/human-interface-guidelines/motion) —
    motion should communicate and support understanding rather than distract.
20. [Material Design 3: Usability](https://m3.material.io/foundations/usability) —
    usable components, clear states, and predictable interaction.
21. [Material Design 3: Typography](https://m3.material.io/styles/typography/overview) —
    type scale and roles for readable hierarchy.

## Performance and form-quality references

22. [web.dev: Core Web Vitals](https://web.dev/explore/learn-core-web-vitals) —
    loading, responsiveness, and visual stability as real user experience.
23. [Chrome Lighthouse: Non-composited animations](https://developer.chrome.com/docs/lighthouse/performance/non-composited-animations) —
    animation can increase layout shift and performance cost.
24. [Chrome Lighthouse: Font display](https://developer.chrome.com/docs/lighthouse/performance/font-display) —
    font loading choices affect visible text and layout shifts.
25. [Chrome Lighthouse: Excessive DOM size](https://developer.chrome.com/docs/lighthouse/performance/dom-size) —
    unnecessary DOM complexity can harm performance.
26. [GOV.UK Design System](https://design-system.service.gov.uk/) —
    evidence-led, accessible, reusable component and content guidance.
27. [GOV.UK Design System: Button](https://design-system.service.gov.uk/components/button/) —
    button purpose, wording, hierarchy, and interaction guidance.
28. [Baymard: Adaptive Validation Error Messages](https://baymard.com/blog/adaptive-validation-error-messages) —
    form errors should help users understand and correct the specific problem.
